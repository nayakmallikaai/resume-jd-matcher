Resume-JD Matcher
Intelligent semantic matching for hiring.
Two-layer architecture combining vector search and LLM reasoning.
Press → to continue
Architecture
Layer 1: Vector Search
Resume PDF → Embeddings → PostgreSQL + pgvector
Fast retrieval (~100ms) using IVFFlat indexing
Returns top-N semantic matches
Layer 2: Re-ranking
Claude Haiku evaluates semantic fit
Detects: keyword stuffing, domain mismatch, stale expertise
Returns ranked candidates with reasoning
Tech Stack
Backend — FastAPI (async)
Database — PostgreSQL + pgvector
Embeddings — sentence-transformers (local)
PDF Processing — pdfplumber
LLM — Anthropic Claude Haiku
Self-contained. No external dependencies. Runs locally or cloud.

How It Works
Input: Job Description
"Senior Backend Engineer, 5+ years distributed systems,
Python, Kafka, Kubernetes. Led teams, owned data pipeline."
Processing
Extract structured requirements (skills, seniority, domains)
Vector search candidates → retrieve top matches
Claude re-ranks with semantic reasoning
Output: Ranked Candidates
#1 Jordan Kim (9y senior) — Distributed systems expert
#2 Elena Vasquez (12y staff) — Led infra teams
#3 Marcus Osei (7y senior) — Kafka + Kubernetes strong
Why It Works
Semantic matching understands context
"Time-series ML" ≠ "LLM fine-tuning" even if both are ML
Depth matters more than keyword density
Humble senior beats verbose junior every time
Explainability built in
You see why each candidate ranked where they did
Honest about uncertainty
Vague specs return medium/low confidence (no false positives)
